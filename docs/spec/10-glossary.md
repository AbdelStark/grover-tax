# Glossary

Terms used throughout the spec corpus. When two communities use the same word differently, the meaning here is the one binding within this repo.

## A

**Apples-to-apples** — A property of a comparison: that the only differences between the two compared paths are the ones being measured. In this project, total apples-to-apples is impossible (e.g., the field differs structurally between provers); the disclosures section of `RESULTS.md` names every divergence. See `RFC-0005`, `RFC-0011`.

## B

**Backend** — A prover implementation. This project compares two backends: SP1 (Succinct Labs) and Stwo (StarkWare). Not used to mean "server" or "infrastructure tier".

**BabyBear** — A 31-bit prime field (`2^31 − 2^27 + 1`) used by SP1's STARK. Structural to SP1, not a tunable. See `RFC-0011` for why field choice is a disclosure, not a knob.

**Blake2s** — A 32-byte-output ARX hash. Used on the Stwo side as the circuit commitment because (a) Stwo Cairo has a Blake2s built-in, (b) it is bit-oriented and in the same structural family as SHA-2, making the comparison more honest than Poseidon would be. See `RFC-0005`.

## C

**`C` (the circuit)** — The reversible classical circuit composed of `{NOT, CNOT, Toffoli}` gates that realises one elliptic-curve point addition over secp256k1. The witness in the ZK proof. The full byte serialisation is published in `fixtures/v0.1.json` for third-party verification.

**Cairo** — StarkWare's language for writing STARK-provable programs. The Stwo prover ingests Cairo. `stwo-side/circuit.cairo` is this project's program. Pinned in `versions.lock`.

**CI rig** — The continuous-integration Linux box (see `04.2`). Regression-only; never substitutes for the reference rig in headline numbers.

**Cold-cache run** — The first invocation of a prover in a series, where filesystem and CPU caches are cold. Always discarded per `D-INV-3`.

**Commitment** — A fixed-length hash binding the verifier to a specific `C` byte serialisation. SP1 side: SHA-256. Stwo side: Blake2s. Both bind the same `C`. See `RFC-0005`.

**Constraint count** — The total number of arithmetic constraints in the proof, as reported by the prover with `RUST_LOG=info`. Captured as part of M7 via the `CONSTRAINTS:` log line. Stwo and SP1 report constraint counts in their own native units; the headline does not ratio constraint counts.

## D

**Discard** — A measured run that is not counted in the published distribution. Reasons enumerated in `04-error-model.md` and `D-INV-2`. Recorded in `results/discards.log` with reason.

**Day-1 / Day-2** — Two independent run series separated by at least one cold-boot. Used to estimate measurement noise. The median delta on M1 must be ≤ 5%; greater triggers a `[STABILITY BREACH]` flag in `RESULTS.md`. See `RFC-0010`.

## E

**End-to-end** — The full `git clone` → `RESULTS.md` reproduction sequence. Bounded by the 30-minute target and 45-minute ceiling in `08-performance-budget.md`.

**Environment hygiene** — The set of OS-level preconditions that must hold for a measurement to be valid (AC power, low-power mode off, no GPU residency, no swap, env vars set, affinity set). Asserted by `scripts/preflight.sh`. See `RFC-0010`.

## F

**Fixture** — The deterministic, canonical input file for both provers. `fixtures/v0.1.json`. Schema in `03-data-model.md`. Generated by `gen_fixtures.py`. Frozen post-generation.

**Field choice** — The base prime field used by a prover's internal arithmetic. BabyBear (SP1) vs M31 (Stwo). Structural; reported as a disclosure, not folded into the headline.

## G

**Gate** — One element of `C`. Opcodes: `NOT` (1-bit flip), `CNOT` (controlled XOR), `Toffoli` (doubly-controlled XOR). `NOP` (0) is reserved for padding `C` to a power-of-two length.

**Gate-list** — The sequence of `Gate` records that constitutes `C`. Canonical serialisation in `03-data-model.md`.

**Groth16** — A pairing-based SNARK. SP1 wraps its STARK proof with a Groth16 SNARK to produce a constant-size proof. Requires a trusted setup. See `RFC-0005` and `06-security.md`.

**`gnu-time`** — The GNU utility `time -v`, which reports peak RSS, user CPU, sys CPU. Distinct from the shell built-in. On macOS, installed via `coreutils` as `gtime`; on Linux, `/usr/bin/time`.

## H

**Headline** — The top-of-`RESULTS.md` table and the single ratio `t_SP1_Groth16 / t_Stwo`. The "result" of the project.

**Hyperfine** — A command-line benchmark tool that runs a command repeatedly and reports timing distribution as JSON. The only acceptable wall-clock source for M1 and M5 in this project.

## I

**IQR** — Interquartile range. `Q3 − Q1`. Reported alongside median for every distribution.

## L

**Locked** — A value that has been decided and recorded in `versions.lock`, `WORKLOAD.md`, or a frozen fixture, and that may not change without a version bump. The opposite of `TBD`.

## M

**M1..M10** — The fixed metric set. Definitions in `05-observability.md` and `RFC-0008`.

**M31** — The Mersenne-31 prime field (`2^31 − 1`). Stwo's native field. Stwo Cairo arithmetic is natively in M31; 256-bit operations require a multi-limb representation (9 × 31 bits in this project). See `RFC-0004`.

**Measured run** — An invocation of a prover that is *not* discarded and *does* contribute to the published distribution. Subject to all preconditions in `04-error-model.md.MEASUREMENT`.

## N

**`N`** — The number of test cases in `T`. Pinned in `WORKLOAD.md` from upstream `zkp_ecc` defaults. See `RFC-0001`.

**Non-determinism** — Any behaviour where running the same command twice with the same inputs yields different on-disk results. In this project, prover output bytes may differ (provers may include randomness in proofs) but timings, schemas, fixtures, and analysis outputs are deterministic. Non-determinism in `gen_fixtures` is a defect (`FIXTURE.SEED_DRIFT`).

## P

**Patch (SP1)** — `sp1-side-patches/0001-read-fixtures-from-json.patch`. The single, < 50-line diff applied to `tanujkhattar/zkp_ecc` to read fixtures from JSON and emit proof to a CLI-supplied path. See `RFC-0006`.

**Point-addition** — The elliptic-curve operation `(P, Q) ↦ P + Q` over secp256k1, in affine coordinates. The atomic operation that `C` realises.

**Prover** — A program that takes a witness and constraints and emits a proof. SP1 and Stwo are the two provers compared.

## R

**RAYON_NUM_THREADS** — Environment variable controlling Rust's `rayon` parallel iterator pool. Set to `1` for measured runs.

**Reference rig** — The canonical hardware on which headline numbers are produced. M4 Max, 48 GB, macOS 26.2. See `04.1`.

**Reproducer** — A third party who clones the repo and runs `./scripts/run_all.sh` to verify the published numbers.

**Run** — One invocation of `bin/run_<prover>.sh`. Subject to hygiene preconditions.

**Run series** — `N` runs of one prover under one `hyperfine` invocation (default `N=10` for proof gen, `N=50` for verify).

**RSS** — Resident set size. The portion of a process's memory currently held in RAM. Captured by `gnu-time -v` as M2.

## S

**SHA-256** — The hash used on the SP1 side as the circuit commitment. Native to SP1's example. The choice is not under our control on the SP1 side. See `RFC-0005`.

**SP1** — Succinct Labs' STARK-based zkVM, with a Groth16 wrap producing the final proof. Pinned by Cargo.lock in `sp1-side/`.

**SP1+Groth16** — The full SP1 stack including the Groth16 wrap. The compound term is used in `RESULTS.md` to distinguish the *wrapped* proof from a raw SP1 STARK.

**Stwo** — StarkWare's STARK prover. The newer of their stacks; native M31 arithmetic; no trusted setup. Pinned by SHA in `versions.lock`.

**SHA-2 XOF** — The extendable-output construction used by `gen_fixtures.py` to derive test cases deterministically from `SEED`.

## T

**`T`** — The public set of `N` test cases `{(x_i, y_i)}` against which `C` is asserted. Part of the public input to both proofs.

**`taskpolicy -c utility`** — macOS-specific affinity hint that confines a process to performance cores under the `utility` QoS class. Used because macOS does not expose hard single-core affinity. See `RFC-0009`.

**`taskset -c 0`** — Linux-specific single-core affinity. Used on the CI rig.

**Trace rows** — The number of rows in the prover's execution trace. Captured as part of M7 via the `TRACE_ROWS:` log line.

**Trusted setup** — A ceremony that produces a structured-reference-string for Groth16. Required on the SP1 side; absent on the Stwo side. Reported as a structural disclosure, not in the headline ratio. See `06-security.md`.

## V

**`versions.lock`** — The pinned-toolchain manifest. Schema in `03-data-model.md`. Regenerated by `scripts/lock_versions.sh`. Required to be in-sync with the live toolchain at run time. See `RFC-0012`.

**Verifier** — A program that checks a proof. Both verifiers are taken from upstream unmodified. See `06-security.md`.

## W

**`W`** — Bit-stripe width used in `sim.rs`'s hot loop. Pinned from upstream source. See `RFC-0001`.

**`WORKLOAD.md`** — The frozen contract that ties this project's fixture and Cairo to upstream `zkp_ecc` parameters. Six fields, all locked before any Cairo is written. See `RFC-0001`.

## X

**XOF** — Extendable-output function. A hash construction whose output length is parameterisable. Used here to deterministically derive arbitrary-length pseudorandom byte streams from `SEED`.

## Z

**Zero-knowledge proof (ZKP)** — A proof that attests to the truth of a statement without revealing the witness. In this project: the prover convinces the verifier that a `C` exists realising secp256k1 point-addition over `T`, without revealing the gate-list of `C` to the verifier (although the gate-list is published out-of-band in `fixtures/v0.1.json` for benchmarking purposes).
