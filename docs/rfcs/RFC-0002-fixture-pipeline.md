# RFC-0002: Fixture generator and schema

- Status: Accepted
- Authors: maintainer
- Created: 2026-05-13
- Target milestone: v0.1

## Summary

This RFC specifies `python/grover_tax/gen_fixtures.py` and the `fixtures/v0.1.json` schema it produces. The generator is fully deterministic given the pinned `SEED` and `WORKLOAD.md`. The fixture is the apples-to-apples bridge between the two provers: both ingest the same bytes; the only intentional divergence is the binding hash (SHA-256 on SP1 side, Blake2s on Stwo side, both committed to the same `circuit_byte_serialisation_hex`).

## Motivation

A benchmark whose inputs differ across the two provers proves nothing. The PRD §6 establishes the *one* permitted divergence (the commitment hash) and the procedure for making everything else bit-identical. This RFC turns that procedure into:

- A precise generator algorithm with cross-validation against `coincurve`.
- A JSON Schema for `fixtures/v0.1.json` (`docs/spec/schemas/fixture-v0.1.schema.json`).
- A `--check` mode that surfaces hand edits or generator drift.

Without all three, fixture-tampering is undetectable.

## Goals

- A single Python entry point (`uv run gen-fixtures`) that emits `fixtures/v0.1.json` deterministically.
- A JSON Schema that validates the fixture and is exercised in CI.
- A `--check` mode usable in CI and by reviewers (`gen-fixtures --check` exits non-zero if regenerated bytes differ from on-disk bytes).
- Cross-validation against the Python reference simulator (`sim_reference.py`, RFC-0003) and against `coincurve` reference math.

## Non-Goals

- A general-purpose fixture framework. This generator is bound to *one* workload.
- Network access at generation time. The generator runs fully offline.
- Multiple output formats. JSON only; the schema is in `03-data-model.md`.

## Proposed Design

### Inputs

Constants in `python/grover_tax/gen_fixtures.py`:

```python
SEED: bytes = b"grover-tax-v0.1-2026-05"  # ASCII bytes, fixed
N: int = <value from WORKLOAD.md>
W: int = <value from WORKLOAD.md>
CIRCUIT_SERIALISATION_FORMAT_VERSION: int = 1
```

`SEED` is byte-stable. `N` and `W` are *read* from `WORKLOAD.md` at module-load time and asserted non-`TBD`. The constants are not function-call arguments; the generator is non-configurable. Configurability is the path to undetected workload drift.

### Algorithm (binding)

```
def main():
    workload = load_workload_md("WORKLOAD.md")
    if workload.has_tbd():
        raise FixtureError("FIXTURE.WORKLOAD_NOT_PINNED")

    seed_bytes = sha256(SEED).digest()

    rng = ShakeXOF(seed_bytes)            # SHA-2-style XOF as per PRD §6.2 step 1

    # 1. Construct C (gate-list for secp256k1 point-add)
    C = build_secp256k1_pointadd_circuit(
        bit_stripe_width=W,
        gate_count=workload.gate_count,
    )

    # 2. Generate N test cases
    test_cases = []
    for i in range(N):
        x_i = sample_x_pair(rng)          # two affine secp256k1 points (P, Q)
        # 3. Reference math: y_i = P + Q via coincurve
        y_i = coincurve_add(*x_i)
        # 4. Cross-validate via Python reference simulator
        y_i_sim = sim_reference.run(C, x_i)
        if y_i_sim != y_i:
            raise FixtureError("FIXTURE.CROSS_VALIDATION_FAIL")
        test_cases.append((x_i, y_i))

    # 5. Canonical byte serialisation of C
    C_bytes = canonical_serialise(C)

    # 6. Commitments
    sha256_hex = hashlib.sha256(C_bytes).hexdigest()
    blake2s_hex = hashlib.blake2s(C_bytes).hexdigest()

    # 7. Emit
    fixture = {
        "version": "v0.1",
        "generator_commit": git_head_sha(),
        "workload_pin_commit": workload.upstream_commit,
        "seed_hex": seed_bytes.hex(),
        "n_samples": N,
        "bit_stripe_width": W,
        "circuit_serialisation_format_version": CIRCUIT_SERIALISATION_FORMAT_VERSION,
        "circuit_byte_serialisation_hex": C_bytes.hex(),
        "circuit_commitment_sha256_hex": sha256_hex,
        "circuit_commitment_blake2s_hex": blake2s_hex,
        "test_cases": [
            {"x_hex": serialize_x(x).hex(), "y_hex": serialize_y(y).hex()}
            for x, y in test_cases
        ],
    }

    if "--check" in sys.argv:
        on_disk = json.loads(open("fixtures/v0.1.json").read())
        if normalise(on_disk) != normalise(fixture):
            raise FixtureError("FIXTURE.DRIFT (--check mode)")
    else:
        atomic_write("fixtures/v0.1.json", json.dumps(fixture, indent=2, sort_keys=False))
```

`normalise()` strips fields not relevant to byte-stable comparison (specifically: `generator_commit`, which depends on the repo state at generation time).

### Canonical byte serialisation

Specified in `03-data-model.md` §"Canonical byte serialisation of `C`". Binding: little-endian, magic `b"GTV1"`, fixed-size `Gate` records. The serialiser is implemented in Python (`grover_tax.serialise`) and mirrored in Cairo and Rust; cross-impl byte-equality is asserted by test `C-4` (see `07-testing-strategy.md`).

### `--check` mode

Comparison is *byte-level on the normalised dict*. Differences in field order, whitespace, or `generator_commit` do not count as drift. Differences in any other field do.

CI invokes:

```
uv run gen-fixtures --check
```

as a required check. A drift in `fixtures/v0.1.json` therefore fails CI on any PR.

### Determinism guarantees

- `coincurve` is deterministic.
- `hashlib.sha256` and `hashlib.blake2s` are deterministic.
- `ShakeXOF` from a fixed seed is deterministic.
- The order of iteration in `for i in range(N)` is deterministic.
- The canonical serialiser is deterministic (no `set`, no `dict` iteration with key-dependent state).

The only non-deterministic field is `generator_commit`, which is excluded from `--check`'s comparison.

### Schema (excerpt; full schema in `docs/spec/schemas/fixture-v0.1.schema.json`)

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "https://github.com/AbdelStark/grover-tax/blob/main/docs/spec/schemas/fixture-v0.1.schema.json",
  "type": "object",
  "required": [
    "version", "generator_commit", "workload_pin_commit", "seed_hex",
    "n_samples", "bit_stripe_width", "circuit_serialisation_format_version",
    "circuit_byte_serialisation_hex", "circuit_commitment_sha256_hex",
    "circuit_commitment_blake2s_hex", "test_cases"
  ],
  "additionalProperties": false,
  "properties": {
    "version": { "const": "v0.1" },
    "generator_commit": { "type": "string", "pattern": "^[0-9a-f]{40}$" },
    ...
  }
}
```

CI runs `python -m grover_tax.validate_schemas fixtures/v0.1.json`.

## Alternatives Considered

### A1. Random-by-default fixture

Generate fresh test cases on every `gen-fixtures` run. Rejected: defeats the byte-stability commitment and prevents `--check` mode from working.

### A2. Multiple fixture files (one per test case)

`fixtures/v0.1/test_001.json`, `test_002.json`, ... Rejected: one canonical file is easier to cite, hash-verify, and audit; the per-test-case structure lives *inside* the JSON.

### A3. CBOR or msgpack instead of JSON

Smaller on disk, faster to parse. Rejected: JSON is greppable, diff-able, and human-inspectable in a browser. Fixture size is not the bottleneck.

### A4. SHA-3 / Shake instead of SHA-2 for XOF

Rejected: PRD §6.2 specifies SHA-2 XOF. The choice is part of the workload pin (see `RFC-0001`).

## Drawbacks

- Re-running `gen-fixtures` after a successful `WORKLOAD.md` update overwrites the fixture in place. Mitigated by the version-bump discipline in `RFC-0001` (re-pin → bump filename to `v0.2.json`).
- The full byte serialisation of `C` is hex-encoded in JSON, which inflates size by ~2×. Acceptable: a few hundred KB for the full fixture, well within budget.

## Migration / Rollout

First-time use. No migration. Day-1 execution:

1. Land `WORKLOAD.md` with no `TBD`.
2. Run `uv run gen-fixtures`. Confirm cross-validation passes.
3. Commit `fixtures/v0.1.json`.

## Testing Strategy

- **F-T1**: Determinism. Run `gen-fixtures` twice; assert byte-identical output modulo `generator_commit`.
- **F-T2**: `--check` mode positive. After fresh generation, `gen-fixtures --check` exits 0.
- **F-T3**: `--check` mode negative. After `sed -i 's/y_hex/y_hex_X/' fixtures/v0.1.json`, `gen-fixtures --check` exits 4 with `FIXTURE.DRIFT`.
- **F-T4**: Schema validation. The emitted fixture validates; 10 hand-crafted malformed fixtures all fail validation with the correct field-level error.
- **F-T5**: Cross-validation against `coincurve` for 100 randomly drawn `(P_i, Q_i)` pairs (separate from the in-fixture test cases).
- **F-T6**: Commitment self-check. After generation, `sha256` and `blake2s` of `circuit_byte_serialisation_hex` match the recorded commitments.
- **F-T7**: Canonical-serialiser cross-impl. Python vs Rust vs Cairo byte-equality on a known gate list.
