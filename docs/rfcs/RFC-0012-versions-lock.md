# RFC-0012: `versions.lock` format and regeneration

- Status: Accepted
- Authors: maintainer
- Created: 2026-05-13
- Target milestone: v0.1

## Summary

`versions.lock` is the pinned-toolchain manifest. It records every version, commit SHA, and host attribute that affects measured numbers. It is regenerated by `scripts/lock_versions.sh`, committed to the repo, and re-asserted by `preflight.sh` before every measured run. Toolchain drift relative to the committed `versions.lock` invalidates the entire run series.

## Motivation

A benchmark that does not record what produced its numbers is hearsay. The PRD §5.1 enumerates a toolchain matrix; this RFC turns the matrix into a structured file with regeneration and assertion machinery, so a reader six months later can answer "what produced these numbers?" by reading one file.

## Goals

- A single JSON file (`versions.lock`) with the schema in `03-data-model.md`.
- A regeneration script (`scripts/lock_versions.sh`) that produces it deterministically from the live toolchain.
- An in-tree assertion (`preflight.sh`) that the live toolchain matches the committed lock.
- `RESULTS.md` references `versions.lock` so the reader can correlate.

## Non-Goals

- A full SBOM. `versions.lock` records *direct* toolchain dependencies, not the transitive graph. `uv.lock` and `Cargo.lock` cover their respective transitives.
- Cross-version compatibility tables (e.g., "this `versions.lock` is compatible with that `versions.lock`"). One lock per release; comparison happens at the human-PR level.

## Proposed Design

### File location and format

`versions.lock` is at the repo root. JSON, schema in `03-data-model.md`. Pretty-printed with 2-space indent and sorted keys for byte-stable diffing.

### `scripts/lock_versions.sh`

```bash
#!/usr/bin/env bash
# scripts/lock_versions.sh — regenerate versions.lock from the live toolchain.
set -euo pipefail

OUT="${1:-versions.lock}"
DRY="${DRY:-0}"

cat > /tmp/lock.$$.json <<JSON
{
  "schema_version": 1,
  "generated_at": "$(date -u +%Y-%m-%dT%H:%M:%SZ)",
  "generator_commit": "$(git rev-parse HEAD)",
  "rustc": {
    "version": "$(rustc --version --verbose | awk '/^rustc/{print $2}')",
    "commit_hash": "$(rustc --version --verbose | awk '/commit-hash/{print $2}')",
    "host": "$(rustc --version --verbose | awk '/^host/{print $2}')"
  },
  "cargo": { "version": "$(cargo --version | awk '{print $2}')" },
  "sp1": {
    "version": "$(awk '/^name = "sp1-/ {ok=1} ok && /^version =/ {print $3; exit}' sp1-side/Cargo.lock 2>/dev/null || echo unknown | tr -d '\"')",
    "sp1up_toolchain": "$(sp1up --version 2>/dev/null | awk '{print $2}' || echo unknown)"
  },
  "stwo": {
    "commit": "$(cd stwo 2>/dev/null && git rev-parse HEAD || echo unknown)",
    "remote": "https://github.com/starkware-libs/stwo"
  },
  "cairo": { "version": "$(cairo-compile --version 2>/dev/null || echo unknown)" },
  "uv": {
    "version": "$(uv --version | awk '{print $2}')",
    "sha256": "$(shasum -a 256 "$(which uv)" | awk '{print $1}')"
  },
  "python": { "version": "$(uv run python --version 2>&1 | awk '{print $2}')" },
  "hyperfine": { "version": "$(hyperfine --version | awk '{print $2}')" },
  "gnu_time": {
    "version": "$(gtime --version 2>&1 | head -n1 || /usr/bin/time --version 2>&1 | head -n1)",
    "binary": "$(command -v gtime || command -v /usr/bin/time)"
  },
  "host": {
    "platform": "$(uname | tr '[:upper:]' '[:lower:]')",
    "arch": "$(uname -m)",
    "model": "$(sysctl -n hw.model 2>/dev/null || cat /sys/devices/virtual/dmi/id/product_name 2>/dev/null || echo unknown)",
    "cpu_brand": "$(sysctl -n machdep.cpu.brand_string 2>/dev/null || grep -m1 '^model name' /proc/cpuinfo | cut -d: -f2- | xargs || echo unknown)",
    "cores_total": $(sysctl -n hw.ncpu 2>/dev/null || nproc),
    "ram_gb": $(($(sysctl -n hw.memsize 2>/dev/null || cat /proc/meminfo | awk '/^MemTotal:/ {print $2 * 1024}') / 1024 / 1024 / 1024)),
    "kernel": "$(uname -r)"
  }
}
JSON

# Pretty-print with sorted keys for stable diffs.
jq --sort-keys '.' /tmp/lock.$$.json > /tmp/lock.$$.sorted

if [[ "$DRY" == "1" ]]; then
  cat /tmp/lock.$$.sorted
else
  mv /tmp/lock.$$.sorted "$OUT"
fi

rm -f /tmp/lock.$$.json
```

The script depends on: `jq`, `awk`, `git`, `rustc`, `cargo`, `uv`, `hyperfine`, `gtime` (or `/usr/bin/time`), platform-dependent commands. All are in the toolchain matrix.

### `preflight.sh` assertion

```bash
# In preflight.sh
ACTUAL=$(./scripts/lock_versions.sh --dry-run 2>/dev/null)
EXPECTED=$(cat versions.lock)
if [[ "$(echo "$ACTUAL" | jq 'del(.generated_at, .generator_commit)')" != \
      "$(echo "$EXPECTED" | jq 'del(.generated_at, .generator_commit)')" ]]; then
  echo "MEASUREMENT.VERSIONS_DRIFT: live toolchain differs from versions.lock" >&2
  diff <(echo "$EXPECTED" | jq 'del(.generated_at, .generator_commit)') \
       <(echo "$ACTUAL"   | jq 'del(.generated_at, .generator_commit)')   >&2
  exit 5
fi
```

`generated_at` and `generator_commit` differ on every regeneration; they are excluded from drift comparison.

### Regeneration discipline

`versions.lock` is regenerated:

- On the first day of work (initial pin).
- Whenever a toolchain version is intentionally bumped (a separate PR titled `Bump <component>`, body explains why).
- Never silently.

After regeneration, `RESULTS.md` is regenerated by `analyze.py` (it reads `versions.lock` for host metadata). If the prior `results/` are still relevant to compare, they are archived under `results/archive/<date>/` per `09-release-and-versioning.md` §Archival.

### Cross-reference invariants

- `versions.lock.sp1.version` must equal the `sp1-side/Cargo.lock` derived version. CI asserts.
- `versions.lock.stwo.commit` must equal `git submodule status` for the `stwo` submodule (or the pinned dependency in `stwo-side/Cargo.toml`, depending on consumption model).
- `versions.lock.uv.sha256` must equal `shasum -a 256` of the `uv` binary at the path the script resolved. A drift indicates the user has a different `uv` build than the pinned one.

### Schema invariants

(Defined in `03-data-model.md` §"Versions lock". Cross-link for completeness.)

V-INV-1..4. CI runs `python -m grover_tax.validate_schemas versions.lock` on every PR.

## Alternatives Considered

### A1. Use `nix flake.lock` for full reproducible build

Pros: cryptographically verifiable; entire dependency graph pinned.

Cons:
- Nix is a heavy dependency for a benchmark project; a reproducer must install Nix.
- macOS Nix on Apple Silicon has known rough edges.
- The marginal precision gain (full transitive lock vs direct lock) does not change the headline.

Rejected for `v0.1`. Considered for a hypothetical `v1.0` once the benchmark is more cited and reproducibility matters more.

### A2. TOML instead of JSON

Pros: more human-readable for nested values.

Cons:
- JSON is well-supported by `jq` and CI tooling.
- The lock is generated, not hand-edited; readability is for the JSON-pretty-print, not the raw spec.

Rejected.

### A3. Embed `versions.lock` content into `RESULTS.md`

Pros: one-file reproduction recipe.

Cons:
- Inflates `RESULTS.md` to ~200 lines of metadata.
- The reference (`versions.lock` (sha256: ...)`) is sufficient.

Rejected.

### A4. Skip the host attributes; record only versions

Pros: smaller, more portable lock file.

Cons:
- Host details (CPU brand, kernel, model) affect numbers materially. Recording them is the bare minimum.

Rejected.

## Drawbacks

- The lock script is shell-heavy and platform-specific. Mitigated by tests on both macOS and Linux CI.
- The drift check relies on `lock_versions.sh --dry-run` producing identical output for identical toolchain state; this is verified by `V-T1` below.
- Pretty-printing JSON with `jq --sort-keys` is deterministic but slow on large objects. Not a concern at this lock size.

## Migration / Rollout

First-time. Day-1 regeneration; commit; PR-review; merge before any measured run.

## Testing Strategy

- **V-T1**: Determinism of `lock_versions.sh --dry-run`: run twice with no toolchain change, diff outputs, exclude `generated_at` and `generator_commit`, assert identical.
- **V-T2**: Drift detection: stage a fake `rustc` (e.g., `PATH=/tmp/fake-rustc:...`) that reports a different version, run `preflight.sh`, assert exit 5.
- **V-T3**: Cross-reference: `versions.lock.sp1.version` matches `awk` over `sp1-side/Cargo.lock`.
- **V-T4**: Schema validate `versions.lock` in CI.
- **V-T5**: Bump test: modify `versions.lock`, run a measured pass, assert preflight catches the inconsistency.
